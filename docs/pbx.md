# מרכזייה עצמית — חיבור Asterisk ל-ha_ivr

ספק **מרכזייה עצמית** מפעיל את התפריט וההתראות של ha_ivr מול מרכזייה
שרצה ברשת שלכם — Asterisk, FreeSWITCH, או כל PBX שיודע להריץ סקריפט
ולבצע בקשת HTTP. שני הקצוות שלכם.

**היתרון:** אין צורך בכתובת חיצונית, בדומיין או ברישום מול ספק. הכל
עובד ברשת המקומית — המרכזייה פונה ל-Home Assistant בכתובת פנימית,
וה-Home Assistant פונה למרכזייה חזרה. שום פורט לא נחשף לאינטרנט.

**החלוקה:** המוח — התפריט, הזיהוי, ההתראות — יושב כולו ב-ha_ivr
ונבנה מהממשק הגרפי. המרכזייה היא שכבת תעבורה דקה: היא עונה לשיחה,
מעבירה את מצבה ל-ha_ivr, מקריאה את מה שחוזר, ואוספת הקשה. התפריט אינו
מקודד בדיאלפלן — כל שינוי נעשה ב-HA, לא בשרת.

> **חבילת ההתקנה הנלווית** מתקינה Asterisk עם כל החבילות הדרושות,
> מציבה את הסקריפטים, וכותבת את קובצי ההגדרה שמתוארים כאן. מסמך זה
> מפרט את ההגדרות עצמן — מה כל אחת עושה ואיך שני הצדדים מתחברים —
> כדי שתוכלו לאמת, להתאים, או להגדיר ידנית.

---

## דרישות מוקדמות

- מרכזייה עם טראנק PJSIP יוצא אחד לפחות (ספק SIP שדרכו מחייגים).
- מנוע TTS מקומי להקראה. ההתקנה משתמשת ב-`edge-tts`, שממיר טקסט
  ל-WAV ב-8kHz — הפורמט שהטלפוניה מקריאה.
- קישוריות רשת דו-כיוונית בין המרכזייה ל-Home Assistant.

---

## חלק א׳ · התפריט הנכנס

### 1. הוספת הספק ב-Home Assistant

הגדרות → מכשירים ושירותים → הוסף אינטגרציה → **IVR**, ובחירת הספק
**מרכזייה עצמית**. אחרי היצירה, מסך ההגדרות הראשון מציג את **כתובת
נקודת הקצה עם הטוקן** — משהו כמו:

```
http://192.168.1.10:8123/api/ha_ivr/pbx/<TOKEN>
```

זו הכתובת שהמרכזייה תפנה אליה בכל צעד בשיחה. העתיקו אותה.

> הטוקן הוא הסיסמה לנקודת הקצה. אם הוא נחשף — הגדרות → ⋮ → **החלפת
> טוקן**, ואז עדכנו את הכתובת החדשה בקובץ ההגדרה. מומלץ גם להגביל את
> "טווחי ה-IP של הספק" לרשת המקומית בלבד (למשל `192.168.1.0/24`).

### 2. קובץ ההגדרה של הגשר

בקובץ ה-config של הגשר במרכזייה (`agi-bin/config.ini`):

```ini
[ha_ivr]
pbx_url     = http://192.168.1.10:8123/api/ha_ivr/pbx/<TOKEN>
edge_say    = /var/lib/asterisk/agi-bin/edge_say.sh
error_audio = beeperr
```

- `pbx_url` — הכתובת שהעתקתם, כולל הטוקן.
- `edge_say` — נתיב לסקריפט ההקראה המקומי.
- `error_audio` — צליל שמושמע אם הפנייה ל-HA נכשלת.

### 3. הסקריפטים ב-agi-bin

ב-`agi-bin` של המרכזייה:

- `ha_relay.py` — הממסר: פונה ל-`pbx_url`, מקריא את התשובה, אוסף
  ספרה, וחוזר. זהו כל מה שרץ בצד המרכזייה עבור התפריט.
- `edge_say.sh` — ההקראה המקומית (טקסט → WAV).

### 4. הדיאלפלן

הקשר אחד עבור התפריט. הפנו אליו את המסלול הנכנס:

```ini
[from-external]
exten => _X.,1,Goto(s,1)

exten => s,1,NoOp(--- ha_ivr relay ---)
 same => n,Answer()
 same => n,Set(CHANNEL(language)=he)
 same => n,Set(PBX_GOTO=)
 same => n,AGI(ha_relay.py)

 ; PBX_GOTO מתמלא כשפריט ב-ha_ivr הוא "מעבר" (goto). ריק = תפריט
 ; רגיל שהסתיים.
 same => n,GotoIf($["${PBX_GOTO}" != ""]?transfer)
 same => n,Hangup()

 ; מעבר ליעד שהממסר נקב בו — למשל שלוחת ה-VoIP של HA לעוזר הקולי.
 same => n(transfer),Dial(PJSIP/${PBX_GOTO},30,gH)
 same => n,Hangup()

exten => i,1,Hangup()
exten => t,1,Hangup()
```

`Answer` פעם אחת בכניסה; אין `Answer` שני ביעד המעבר. בזה נגמרת
הגדרת התפריט — כל השאר נבנה ב-ha_ivr מכפתור ה-`+` בכרטיס האינטגרציה.

## חלק ב׳ · התראות קוליות

ההתראות מרוכזות ב-ha_ivr: כל נמען שמוסיפים לאינטגרציה הופך לישות
`notify`, וכשהיא נשלחת היא פונה ל-webhook שרץ במרכזייה — והוא מחייג
למספר ומקריא את הטקסט.

### 1. שירות ה-webhook

`call_trigger.py` רץ כשירות ומאזין ל-POST (ברירת מחדל: פורט `5000`,
מסלול `/ha`). ההגדרות בקובץ סביבה, `/etc/pbx-alert.env`:

```ini
PBX_ALERT_SECRET=<סוד-אקראי-חזק>
PBX_ALERT_PORT=5000
PBX_ALERT_CALLERID=<המספר שיוצג בשיחה>
```

- `PBX_ALERT_SECRET` — סוד משותף. השירות דורש אותו בכותרת
  `X-Alert-Secret` בכל בקשה, וכך רק מי שמחזיק בו יכול לגרום למרכזייה
  לחייג. אותו ערך מוגדר בצד ה-HA.
- `PBX_ALERT_CALLERID` — מזהה המתקשר שיוצג בשיחת ההתראה.

### 2. הדיאלפלן להתראות

שני הקשרים: אחד מחייג החוצה דרך הטראנק, אחד מקריא את הטקסט.

```ini
; חיוג יוצא — call_trigger שולח Local/<מספר>@ha-outbound ומגדיר HA_TRUNK
[ha-outbound]
exten => _X.,1,NoOp(Dialing out from HA. Target: ${EXTEN}, Trunk: ${HA_TRUNK})
 same => n,Dial(PJSIP/${EXTEN}@${HA_TRUNK})
 same => n,Hangup()

; רגל ההקראה — call_trigger מגדיר Context=tts-alerts, ALERT_DATA=<טקסט>
[tts-alerts]
exten => s,1,NoOp(Incoming HA Alert: ${ALERT_DATA})
 same => n,Answer()
 same => n,Wait(1)
 same => n,AGI(ha_say.py,${ALERT_DATA})   ; מסנתז ומשמיע דרך edge_say
 same => n,Hangup()
```

### 3. הגדרה ב-Home Assistant

הגדרות → הרשומה **מרכזייה עצמית** → ⋮ → **הגדרות התפריט**, ומילוי
שלושת שדות ההתראות:

| שדה | ערך | דוגמה |
|---|---|---|
| כתובת שירות ההתראות | כתובת ה-webhook + `/ha` | `http://192.168.1.20:5000/ha` |
| טראנק יוצא להתראות | שם הטראנק שדרכו מחייגים החוצה | `sip_trunk` |
| סוד שירות ההתראות | הערך של `PBX_ALERT_SECRET` | — |

לאחר מכן מוסיפים **נמענים** מכפתור ה-`+` בכרטיס — כל נמען הופך לישות
`notify` נפרדת שמחייגת למספרו.

## החוזה

כל הבקשות והתשובות הן JSON נקי. אין פורמט חבוי — החוזה מוגדר כאן.

**בקשה** (הגשר → ha_ivr):

```json
{"caller": "0501234567", "path": "1/2", "digit": "3", "step": 4}
```

**תשובה** (ha_ivr → הגשר):

```json
{"say": "...", "menu": true, "keys": ["1", "2"],
 "path": "1/2/3", "timeout": 10, "hangup": false}
```

- `menu: true` — לאסוף ספרה ולפנות שוב מאותו `path`.
- `hangup: true` — לנתק אחרי ההקראה.
- `goto` (אם קיים) — להעביר להקשר או לשלוחה שצוינו.

**התראה** (ha_ivr → `call_trigger`):

```json
{"phone": "0501234567", "trunk": "sip_trunk", "text": "..."}
```

בכותרת `X-Alert-Secret: <הסוד>`.

## פתרון תקלות

| תופעה | סיבה נפוצה |
|---|---|
| שיחה נכנסת מנותקת מיד | `pbx_url` שגוי, או הטוקן/ה-IP חסומים ב-HA |
| הקראה קטועה או שקט | טווחי ה-IP של הספק לא כוללים את המרכזייה |
| התראה מחזירה `HTTP 403` | הסוד לא תואם בין הקובץ ל-HA, או ה-IP חסום |
| התראה מחזירה `HTTP 200` אך אין שיחה | שם הטראנק שגוי, או שאין מסלול יוצא דרכו |
| מקש שלא מגיב | הקשר הדיאלפלן מגביל את המקשים — יש לאפשר את כולם |

היומן ב-HA מציג `PBX alert -> HTTP 200`; במרכזייה מופיע
`queued ha call to ... via <trunk>`. שני אלה יחד = הנתיב תקין
מקצה לקצה.
